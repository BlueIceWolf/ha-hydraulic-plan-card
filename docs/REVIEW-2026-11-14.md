# Engineering review — 2026-11-14

## Scope

This branch addresses three concrete configuration failures discovered during the
initial audit against the 2026-11-14 master development brief. It is **not** a
complete implementation of the master brief. In particular, publishing on
`main` must wait for complete hydraulic and UI acceptance.

## Confirmed causes and targeted changes

1. **ETA eHACK cutaway migration false positive.**
   The editor writes `options.eta_view`, but migration maintained a separate,
   incomplete allowlist for `wood_chip_boiler`. Migration now references
   `HPC_FREE.optionKeys`, including `eta_view`. Unknown options continue to
   block automatic migration rather than being deleted.
2. **Mutable global temperature range.**
   `_syncAdditional` previously overwrote `HPC_FREE.colorRange` whenever a
   card rendered. Temperature colouring now accepts an explicit range, and
   card-specific bounds are passed through the integrated SVG, gradients,
   classic circuit colouring and optional free renderer. A changed range
   invalidates the SVG render signature, so a colour edit is not skipped by
   sensor-state caching.
3. **Blank colour bounds silently became zero.**
   The editor now rejects empty numeric inputs and provides a palette preview
   and a reset action. The config-to-range helper also rejects missing,
   empty, reversed and out-of-range values. The historic palette remains the
   default for cards without valid custom bounds.
4. **Entity validation mismatch.**
   Migration used a shorter HA entity-domain allowlist than the editor.
   Migration now uses the same syntactic entity validation as the flexible
   plan editor. This does not imply that all entities represent appropriate
   measurements; only their IDs are validated.

## Compatibility and migration notes

- Existing cards without custom temperature bounds keep the historical
  default palette.
- No component IDs, sensor mappings or hydraulic links are rewritten by the
  temperature-range changes.
- No schema-version increase is necessary for the migration option allowlist.
- Unrecognised option keys, ambiguous coil connections and unsafe topology
  changes remain migration blockers rather than being discarded.
- The publishable `dist/ha-hydraulic-plan-card.js` bundle is generated from
  the six source modules and should remain synchronized with `package.json`.
